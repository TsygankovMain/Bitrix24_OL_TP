# ADR-0002. IMAP-pull как модель доставки писем (вместо forwarding + transactional SMTP)

**Дата:** 2026-05-25
**Статус:** Принято
**Контекст:** R&D-фаза, выбор модели email-моста.

## Контекст

Чтобы доставлять входящие письма клиента в Открытую линию Битрикса, нужна одна из двух моделей:

1. **Pull-модель (IMAP-poller).** Наш сервер раз в минуту опрашивает IMAP-ящик клиента и забирает новые письма.
2. **Push-модель (email forwarding).** Клиент настраивает пересылку с корпоративной почты на наш inbound-адрес `portal-{id}@hub.example.com`. Мы получаем письма мгновенно по SMTP. Ответы оператора отправляем через транзакционный SMTP-провайдер (SendGrid/Postmark) от имени оригинального ящика клиента.

## Решение

Берём IMAP-pull (Вариант 1).

## Обоснование

- **Низкий порог входа для пилотного клиента.** Дать логин-пароль от IMAP-ящика — это 30 секунд работы для админа. Настроить forwarding + SPF/DKIM на стороне клиента — час работы, плюс зависимость от его IT-отдела. На R&D-стадии нам критично, чтобы пилоты вообще доходили до проверки гипотезы, а не отваливались на этапе подключения.
- **Универсальность.** Работает с любым IMAP-провайдером: Яндекс, Mail.ru, корп. Exchange, hosted email — единым механизмом.
- **Меньше зависимостей.** Не нужен транзакционный SMTP-провайдер (SendGrid/Postmark) для исходящих — отправляем напрямую с SMTP клиента. Меньше денег, меньше vendor lock.

## Цена решения (которую принимаем)

- **Задержка до 60 секунд** на входящее письмо. Согласовано: FR-B.1 говорит «≤ 90 секунд», запас есть.
- **Хранение IMAP/SMTP-паролей клиента** в нашей БД (зашифрованных). Это повышает требования к безопасности (см. NFR-2). Принимаем — `libsodium sealed box` достаточно для R&D.
- **Нагрузка на наш сервер растёт линейно по количеству ящиков.** На R&D-объёме (5–10 пилотов) — несущественно.

## Когда пересмотреть

- Если на пилоте обнаружится, что задержка 60 сек убивает UX (клиенты жалуются на «медленный саппорт»).
- Если кто-то из пилотных клиентов критично требует Gmail OAuth — тогда добавляется Push-вариант параллельно (не вместо).
- При выходе в Маркет и росте до сотен порталов — стоимость polling-инфраструктуры может стать заметной.
